# P0d 接頭內力（解析）

模型見 `analysis/joint_loads.py` 檔頭 docstring。單位 N、N·m；模組間距 0.1 m；
**參考尺度：單一模組 hover 重量 m·g = 0.2649 N**；力矩參考 m·g·pitch = 2.65e-02 N·m。
表中「達成率」= 實得角加速度 / 指令；`*` 代表有推力被 clip。接頭勁度 kt=10000 N/m、kr=25 N·m/rad（只影響含迴路構型）。
payload：質點，質量 = 30% 含 payload 總質量，掛在 line 的 x 最大端模組中心，oracle 用新 CoM／J 分配。

## 1. 主張判定

**主張 A（oracle 內力 ≈ 0）：部分成立。**
- hover：所有構型、所有方法的接頭內力 ≤ 1.1e-15·mg（= 0，每個模組自己扛自己的重量）。
- 最大角加速度（pitch/roll 50%、100%）下，oracle 所有接頭最大力 ≤ 0.081·mg（T4 roll100），彎矩/扭矩 ≤ 0.021·mg·pitch。
  相對「完全沒抵消時單模組要承受的慣性力」m·α·max|d|，pitch100 殘差為 0.011–0.083、roll100 為 0.036–0.100（即抵消掉約 90% 以上）。
  所以「趨近 0」在「與 mg 或未抵消的慣性力比」都成立到個位數百分比，但嚴格說不是 0。
- 不為 0 的原因（解析可推）：模組 i 推力和的增量 ∝ r_i 成立；但抵消需要 Iyy_模組 = m·a²（模組內轉子分布的轉動慣量要等於把質量集中在轉子上），
  實際 Iyy = 1.4e-5 vs m·a² = 2.1e-5，所以差一個固定比例，殘差 ∝ α·|r_i|（line3 手算驗證見測試）。
- 內力主要來自分配和幾何不一致：成立。pitch100 下 sym（每模組相同推力）最大力 0.44–0.70·mg（且有 clip、達成率不到 1），
  k 跳規則在「每單位達成角加速度」下，內力是 oracle 的 1.0–72.5 倍（k 越大越接近 oracle，ball=全架時相同）。
- 但 oracle 並非總是 ≈ 0：有 payload 時（oracle 已知新 CoM 與 J），line2/3/4/6/8 的 hover 最大力為 0.10/0.28/0.56/1.26/2.05·mg。
  原因：最小範數解不看質量分布，推力與質量不成比例（均勻質量的前提被打破），重量差要由接頭傳遞，且隨線長以槓桿累積。

**主張 B（yaw 剪力每個方法都有）：成立，但機制和主張敘述不同。**
- yaw100 下所有構型（single 除外）、所有方法的面內剪力皆 > 0（是，見第 3 節）。
- 機制：面內慣性力 −m(α×d_i) 方向在水平面，而推力沿 z、無法抵消，所以面內剪力與分配無關，只取決於實得 α_z（k 跳規則達成率低則剪力成比例變小）。
  最大面內剪力 = 0.05–0.80 m × (m_模組·α_z)（子樹的 Σ|d| 累加，長度單位）。
- yaw 反扭矩「每模組相同、需求 ∝ r」造成的是繞 z 的力矩不平衡（∝ m|d|²α_z），體現在繞 z 的彎矩（面內彎矩）上，而不是剪力。
